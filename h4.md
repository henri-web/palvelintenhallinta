## x) Lue ja tiivistä

### Configuration Management of Distributed Systems over Unreliable and Hostile Networks (Karvinen 2023)

4.12.1 Size and Complexity of Some DSLs

- DSL:ät voivat olla hankalia ja suuria. Tässä analysoitiin Saltin Dsllää ja kerättiin statistiikkoja sen manuaalista

- Saltissa (versio 2017.7.4) on 510 tilafunktiota ja yli 75 000 sanan (yli 20 000 rivin) manuaali ilman ohjausrakenteita. Ehtorakenteet ja silmukat toteutetaan Jinja2-malleilla, jotka tuottavat YAML-koodia – tämä tuo ylläpitäjälle oman matalan tason abstraktiokerroksensa.

- Toinen työkalu puppet taas tarjoaa oletuksena 113 funktiota ja nojaa perinteisten ohjelmointikielten sijaan resurssien määrittelyyn, niiden välisiin riippuvuuksiin sekä omiin rakenteisiinsa, kuten virtuaaliresursseihin toistuvien asetusten hallinnassa.

4.12.2 Use of DSL Functions in Case Configuration

- Vaikka konfiguraationhallintakielissä on paljon ominaisuuksia, suurin osa tuotantotason määrityksistä nojaa vain muutamaan perustoimintoon ja rakenteeseen.

- Taustapalveluita hallitaan usein packagefileservice-mallilla ja asiakassovelluksia packagefile-mallilla. Erityistapaukset hoidetaan `exec` -komennolla.

- Oman keviemmän resurssiabstraktion rakentaminen ei ole niin suuri urakka kuin pelkkien suurten kielioppien perusteella voisi olettaa. Tämä vastaa kokemusta Puppet ja Salt kokemuksista.

4.12.3.1 Dependencies Between Main Functions

- Kappale käsittelee konfiguraatiohallintajärjestelmien (kuten Conftero) funktioiden sisäisiä riippuvuuksia ja arkkitehtuuria järjestelmän kehittäjän näkökulmasta.

- Kehittäjän on ymmärrettävä resurssien riippuvuudet, kun taas käyttäjälle tämä halutaan tehdä helpoksi

- Suoraan kohdejärjestelmään vaikuttavat lopulta vain tiedostotoiminnot ja komentojen ajo.

- Järjestelmä tekee muutoksia vain, jos niiden nykytila poikkeaa tavoitetilasta. (Idempotenttiuksen tarkistus)

- Tietyt alueet kuten pakentinhallinta ja taustapalvelut vaativat, että niitä hallitaan vain yhden komponentin kautta.

- Ylläpitäjät tekevät toimenpiteet yleensä ensin käsin ja automatisoivat vasta sitten, tämän ansioista he osaavat jo yhdistellä perustoimintoja.

## a) Räpylä

Asennetaan postgres käsin. Käytän avuksi Karvisen ohjeita hänen sivuiltaan. 

```
sudo apt-get update
sudo apt-get -y install postgresql
sudo -u postgres createuser henri
sudo -u postgres createdb -O henri
```
Muu toimi paitsi sain viimeisen jälkeen virhe ilmoituksen: createdb: error: database creation failed: ERROR:  database "postgres" already exists. Tämä johtuu siitä, että komennosta puuttui luotavan tietokannan nimi. Jolloin postgres käytti oletuksena jo valmiina olevaa tietokanta nimeä "postgres" joten tehdään viimeinen komentouusiksi

`sudo -u postgres createdb -O henri henri`

## b) Automaatti

Automatisoidaan postgres asennus ansiblella. Tähän käytän ohjeeksi omaa h3 tehtävääni.

`mkdir -p roles/postgres/{files,handlers,tasks}`

Sitten lisätään `micro ansible/site.yml` rooli postgres

Mennään ansible main.yml ja ja lisätään sinne 

```
- apt:
    name: postgresql
    state: presen
```
Ajetaan playbook ja testataan onko toiminnassa ansible-playbook -K site.yml. 

Ajetaan systemctl jotta näämme että Postresql on päällä bootissa 

`systemctl status postgresql --no-pager`

Katsotaan että rooli ja database on vielä olemassa 

`sudo -u postgres psql -c \l -c \du`ja " merkit \ kohtiin tavujen ympärille
